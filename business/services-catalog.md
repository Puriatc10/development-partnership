# Services Catalog — Managed Development Capacity

## 1. Catalog Scope & Pre-Operational Status

This catalog defines the planned software development service offerings, commercial delivery models, and operational delivery standards for partner agencies, studios, and consultants.

> [!IMPORTANT]
> **Pre-Operational Status:** The business is in a pre-operational foundation-building stage. The planned technical delivery team is not yet onboarded and not currently available for client delivery. 
> 
> The services described herein represent **strategic commercial priorities**, not verified team capabilities. All project scopes must undergo mandatory **technical feasibility review** by technical leadership before commercial acceptance.

---

## 2. Strategic Initial Service Priorities

Commercial focus is structured around three core service categories tailored for agencies and visual development studios:

### 2.1. Backend and API Development
- **Core Focus:** Building robust server-side infrastructure, databases, and custom microservices to power partner web and client applications.
- **Key Offerings:**
  - Custom backend architecture and endpoint implementation.
  - RESTful and GraphQL API development and consumption.
  - User authentication, role-based access control (RBAC), and session management.
  - Database schema design, relational data modeling, and data migrations.
  - Third-party SaaS, CRM, payment, and external API integrations.
- **Feasibility Requirement:** Architecture, database selection, and third-party API rate limits must be evaluated per project.

### 2.2. Webflow Extensions and Integrations
- **Core Focus:** Extending Webflow websites beyond native platform and CMS constraints.
- **Key Offerings:**
  - Secure backend connectivity and webhook processing.
  - Advanced membership, gated content, and custom authentication integrations.
  - External database synchronization (e.g., syncing Webflow with PostgreSQL, Supabase, or external data stores).
  - Custom API integrations, automated data pipelines, and third-party service connections.
- **Feasibility Requirement:** Evaluation of Webflow API limitations, CMS collection thresholds, and frontend script performance.

### 2.3. Framer Custom Development
- **Core Focus:** Augmenting Framer websites with production-grade React engineering and interactive logic.
- **Key Offerings:**
  - Bespoke React-based custom components styled and structured for seamless Framer canvas integration.
  - Custom frontend application logic, client-side state management, and real-time data binding.
  - Third-party API integrations, webhook handling, and serverless function connectivity.
  - Advanced functionality and interactive web features exceeding standard visual editing capabilities.
- **Feasibility Requirement:** Evaluation of Framer component runtime constraints, bundle size optimization, and responsive design compatibility.

## 4. Delivery Modes: White-Label vs. Co-Branded

The business provides technical execution under two distinct delivery configurations:

1. **Behind-the-Scenes White-Label (Default Mode):**
   - We operate entirely behind the scenes under the partner's brand.
   - Code repositories, commit histories, staging environments, and deliverables are delivered under the partner's organizational umbrella.
   - No direct contact between our team and the partner's end client. The partner manages 100% of client-facing communications.
2. **Co-Branded Technical Delivery (By Explicit Mutual Agreement Only):**
   - Utilized when a partner explicitly desires to introduce us to the end client as their specialized technical engineering division or development partner.
   - Requires explicit prior written agreement defining client interaction protocols, authorized attendees for technical calls, and shared communication channels.

## 6. Proposed Project Delivery Standards (Internal Defaults)

To ensure operational discipline and avoid misaligned expectations, the following default standards are established:

> [!NOTE]
> These standards represent **internal proposed defaults** for operational governance, not executed contracts. Contractual language and specific figures remain subject to mutual agreement.

1. **Mandatory Written Scope:** No project commences without an agreed written Scope of Work (SOW) defining features, assumptions, technical boundaries, and explicit deliverables.
2. **Milestone Acceptance Criteria:** Each deliverable must include objective criteria for milestone sign-off.
3. **Out-of-Scope Change Management:** Any request falling outside the agreed written SOW requires a formal change request document, technical re-scoping, and commercial approval before execution.
4. **Proposed Revision Limit:** Proposed default of **two revision rounds** for in-scope deliverables. Additional revisions are subject to change requests.
5. **Proposed Acceptance Window:** Proposed standard inspection window of **five business days** following milestone delivery for partner review and feedback. Deliverables without documented defects within this window are deemed accepted.
6. **Agreed Upfront Payment:** Project kickoff requires an agreed upfront deposit. (Specific deposit percentages and milestone payment schedules remain `TBD` in [commercial-policy.md](commercial-policy.md)).
